# Getting Started Entry Activation

## Objective

Make the already-authored, human-first Getting Started material practically discoverable and selectable as a qualified Native Purpose Entry for a first-time user or assistant, without modifying Start's existing orientation contract or duplicating the Docs manual.

## Done Criteria

- A portable Native Session Entry is authored under the existing `what` Entry layout, qualifies against `tiinex.entry.session.v1`, and appears in the existing dynamic Entry catalog without a hardcoded mode.
- The Entry explains how to transition from orientation to a user's natural goal, use the current qualified runtime catalog and schema/companion help, and consider whether ongoing work belongs to the supplied Workspace.
- The Entry respects authority boundaries, avoids automatic scaffolding and identity/Role inferences, and can be composed independently with qualified host Target Entries.
- A complete causal Workspace carrier retains all previously supplied Workspaces; schema/Entry preflight and handoff inspection evidence are recorded outside the returned Workspace.

## Scope

- Use the already accepted Business Documentation And Learning Project and already-carried Docs Getting Started Topic as governing scope and explanatory material.
- Prefer existing Native Session Entry schema, content-source discovery and transport projections. Do not create new schema types, generic guides, or alternative package conventions.
- Preserve the existing Start, Explore, and Resume Entries exactly.

## Dependencies

- Business Project Parent at an immutable GitHub commit must remain resolvable and exact.
- Docs Getting Started material must be qualified from the recipient's currently carried Workspace or from a separately supported qualified material source; mere path presence does not make it current.

## Interpretation Limits

- An Entry definition is not proof of a session occurrence, acceptance, Role-holder assignment, authority to mutate remote state, or achievement of independent first-use acceptance.
- A passing Core preflight or package roundtrip is not evidence that a fresh LLM spontaneously uses Tiinex or that VS Code presents the material.
